# Clash ISP 配置

将用户提供的 ISP 添加到指定订阅，支持直接在已有分组选择，以及“机场节点 → ISP”的中继。默认做持久化的订阅局部增强，不修改远程订阅原文件、不混入其他订阅。

## 确定本次输入

先读取本机实际配置，再补问会影响改动的信息。用户已提供的信息不要重复询问。

| 输入 | 处理方式 |
| --- | --- |
| 目标订阅 | 用户指定名称或 UID；同名多个时用 UID、更新时间及当前启用状态区分，不擅自挑一个。未指定时列出候选并询问。 |
| ISP 列表 | 接受 `HOST:PORT:USER:PASS`、代理 URI 或明确的字段。密码可能含冒号；IPv6 和复杂凭据优先使用 URI/独立字段。不要在回复中复述密码。 |
| 协议及端口 | 以商家明确说明或用户确认的信息为准，不能仅凭端口猜协议。IPRoyal 常见 SOCKS5 为 12324，但不是所有供应商的统一规则。 |
| 目标分组 | 用户指定则沿用。要求 AI 分流时优先复用该订阅已有的 `AI`；否则询问目标分组。已有组不是 `select` 时，不擅自改变其类型。 |
| 直连或中继 | 尊重本次选择；没有提供时询问。地区匹配中继要确认 ISP 的购买地区及订阅中可用的确切节点名。不要按 IP 前缀猜地区，也不硬编码洛杉矶/新加坡节点。 |
| 网站范围 | 仅在要求分流或迁移已有分流时改规则。仅添加候选节点不等于授权所有网站改出口。 |
| 默认选择 | 保留目标分组当前选择；合并旧组时可沿用旧组的当前选择。只有用户要求推荐/默认时才根据验证结果选择。 |

命名要能区分出口与路径，例如 `ISP US-01 (via LA)`、`ISP SG-01 (direct)`。一个 ISP 可有直连和中继两种选项，但不要自动添加用户未要求的变体。

## 执行流程

实际修改 Clash Verge 前阅读 [references/verge-workflow.md](references/verge-workflow.md)，其中包含发现路径、订阅增强顺序、重新激活及持久化选择的注意点。

1. **定位与快照**：确认目标 UID、对应增强文件和当前启用订阅，快照将改的文件及运行时所有分组选择。备份含凭据的文件必须限制权限。非当前订阅只写增强，除非用户要求，不切换启用订阅。
2. **准备局部增强**：把 ISP 写入目标订阅的节点增强，用订阅局部脚本加入已有分组。保留已有脚本、节点、分组和规则；不要以新建同名代理组的方式“覆盖”旧组。
3. **处理规则**：网站规则的目标必须是用户最终操作的分组。若从 `AI-IPRoyal` 合并到 `AI`，检查旧规则引用并迁移，不要留下绕过 `AI` 选择的高优先级旧规则。仅在明确合并旧组、且没有剩余引用时移除旧组。
4. **验证和应用**：先检查候选 YAML 与代理引用，再用可用的 Mihomo `-t` 校验。通过客户端重新生成增强后的配置并重新激活；不能用核心 reload 代替客户端的增强生成。
5. **恢复与持久化**：恢复非目标分组的选择，应用目标选择；同时检查运行时和客户端保存的选择。单独通过 API 切换不保证客户端下次重启还记得。
6. **验证出口**：按指定路径发送 HTTPS 请求，核对实际出口和连接链。报告本次真实测试结果；不要把以前的 10/10、界面绿色状态或延迟当成本次成功证据。

不要为了测试批量切换所有 AI 流量，也不要擅自关闭用户系统代理/TUN。需要测试多个 ISP 时优先使用隔离测试实例或只改变当前测试连接的策略。

## 可复用准备工具

`scripts/prepare_profile.py` 使用 Python 3 和 PyYAML，只读取现有配置并生成待应用文件，不改动实时配置、不发送网络请求。找不到 PyYAML 时选用已有可用环境；不要擅自安装依赖。

列出订阅（不输出订阅链接和凭据）：

```bash
python3 scripts/prepare_profile.py --root "/actual/verge-data" --list
```

按精确 UID 准备变更：

```bash
python3 scripts/prepare_profile.py \
  --root "/actual/verge-data" --profile "ACTUAL_UID" \
  --spec "/private/request.json" --out "/private/new-bundle"
```

输入格式、输出用途和测试方式见 [references/verge-workflow.md](references/verge-workflow.md)。工具可合并节点/规则增强，并以可重复执行的包装块保留原脚本。它不自动创建客户端增强 UID、不删除旧组、不选择运行时节点。应用前比较 `manifest.json` 的源文件哈希并备份；若源文件在准备后变化，停止并重新读取，不能覆盖新变化。

只有当前客户端结构与工具支持的结构匹配时才使用。其他 Clash 客户端按其实际配置机制处理，不强行写入 Verge 元数据。

## 网络与安全判断

- `type: http` 默认是 HTTP 代理，可通过 CONNECT 访问 HTTPS 网站；这不意味着代理入口自身使用 TLS。只有商家明确支持 TLS 到代理入口时才配置 `tls: true`，不要为访问 ChatGPT 强行改入口协议。
- SOCKS5 使用 `type: socks5`；中继只在 ISP 节点上加 `dialer-proxy: "确切的机场节点名"`。最终出口应为 ISP，而非机场。检查中继引用无自指/循环。
- 直连测试须排除环境代理和意外代理链；仅 `curl --noproxy` 不能绕过 TUN/VPN 路由。不能证明直连时明确说明测试边界。
- IPRoyal 的来源 IP/并发来源限制可能导致直连与中继同时测试互相干扰。按路径顺序测试，不把该限制当作所有 timeout 的已证实原因；遇到持续失败先分类 TCP、认证、TLS、目标站错误，再有界重试。
- 凭据只保存在必要的本地配置/私有暂存文件中，不写入此 skill、版本库、公开测试站、命令行参数或最终回复。验证时不关闭目标 HTTPS 证书校验。

## 交付

简短说明：改了哪个订阅/分组、加入哪些路径、当前实际选择、哪些规则改为指向它、本地入口和 ISP 远端端口、本次验证结果、是否仍有未验证项。指出切换只对新连接生效。不要声称域名“全覆盖”，除非确实完成对应审计。
